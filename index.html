MediCore

A lightweight CQRS mediator for .NET 8

First-class interceptors, a service registry, and strictly segregated interfaces — inspired by the mediator pattern, built from scratch.

View on NuGet View on GitHub
dotnet add package MediCore

Quick start

services.AddMediCore(o => o
    .RegisterHandlersFromAssemblyContaining<Program>()
    .AddDefaultInterceptors());              // Logging -> Validation -> Transaction

public sealed record CreateOrder(string Customer) : ICommand<Guid>;

public sealed class CreateOrderHandler : ICommandHandler<CreateOrder, Guid>
{
    public Task<Guid> HandleAsync(CreateOrder cmd, CancellationToken ct) => ...;
}

var id = await sender.SendAsync(new CreateOrder("Acme"));

Why MediCore

Interceptor pipeline

Logging, validation and transactions wrap every request — or write your own with a generic constraint.

CQRS built-in

Commands and queries are distinct types; only commands get wrapped in a transaction.

Service registry

Inspect every discovered handler and interceptor at runtime for diagnostics and startup checks.

Notification strategies

Publish sequentially or in parallel — swap the strategy without touching handlers.

Writing a custom interceptor

A generic constraint decides which requests an interceptor applies to — this one only touches queries:

public sealed class CachingInterceptor<TRequest, TResponse>
    : IRequestInterceptor<TRequest, TResponse>
    where TRequest : IQuery<TResponse>
{
    public async Task<TResponse> InterceptAsync(
        TRequest request, RequestHandlerDelegate<TResponse> next, CancellationToken ct)
    {
        // before ...
        var response = await next();   // skip this line to short-circuit
        // after ...
        return response;
    }
}

o.AddInterceptor(typeof(CachingInterceptor<,>));

Publishing notifications

Publish the concrete type — handlers resolve for the compile-time type, not the interface:

public sealed record OrderPlaced(Guid OrderId) : INotification;

public sealed class SendReceiptEmail : INotificationHandler<OrderPlaced>
{
    public Task HandleAsync(OrderPlaced n, CancellationToken ct) => ...;
}

await publisher.PublishAsync(new OrderPlaced(orderId));

Swap UseParallelNotificationPublisher() in for the default sequential strategy if handlers don't depend on each other's order.
